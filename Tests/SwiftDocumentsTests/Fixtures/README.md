# Fixture provenance

All content is synthetic. No customer documents are used.

- `minimal`, `stored`, `strict`, `relocated`, `features`, `unknown` and `macro` are specification-boundary packages built by `scripts/generate-fixtures.py`. The image in `features.docx` is a generated 1×1 PNG. The VBA part in `macro.docm` is an inert string, not executable VBA.
- `deflate-boundaries.docx` is generated by the same script using Python's independent ZIP/deflate implementation. Its 131,072-character paragraph, 262,144-byte patterned asset and empty compressed asset test inflation / CRC chunk boundaries and incorrect expanded-length declarations. It is synthetic boundary data, not producer-interoperability evidence.
- `python-docx.docx` is independently generated by python-docx. `producer-oracle.json` contains paragraph and table expectations extracted by that library. Regenerate with `python3 scripts/generate-fixtures.py --producer` (requires python-docx). Test execution does not require Python.
- `libreoffice.docx` resaves the python-docx document with LibreOffice 26.2.3.2, Office Open XML Text filter. Default / even / first-page headers and footers become distinct parts; author metadata alone is normalized to synthetic values. Regenerate with `python3 scripts/resave-libreoffice.py --soffice /path/to/soffice`.
- `writer.odt` tests ODF MIME detection; `design.pages` / `spreadsheet.iwork` test IWA root types 10000 / 1. These are not complete application documents or evidence of ODT / Pages reading support.

Keep hand-built boundary fixtures and producer comparisons. Investigate changed producer parts before updating expectations.

- `libreoffice.odt` is the fictional `python-docx.docx` fixture resaved as ODF Text by LibreOffice 26.2.3.2 (writer8). Reproduce with `python3 scripts/resave-libreoffice.py --format odt --soffice /path/to/soffice`. Author fields are normalized to Sample Author, ZIP timestamps to 2026-01-01. Its expected text/table/header/footer values come from the existing independent `producer-oracle.json`; it is not evidence for Pages interoperability.
- ODT and Pages boundary fixtures are constructed independently by `odtPackage`, `iwaArchive`, `iwaFrames` and protobuf helpers in `ODTTests.swift` / `PagesTests.swift`. They contain fictional text only. The older `writer.odt` / `design.pages` files remain minimal detection probes.

- `TableAppearanceTests`, `ODTTypographyTests` and `PagesFormattingTests` build additional fictional packages in memory with the same independent ZIP/Protobuf helpers. They cover table geometry/style fallbacks/history, ODF ruby/tabs/comments and Pages language/style-reset ranges; no producer application or customer data is used.

- `pages-15.4.pages` was produced on macOS by Pages Creator Studio 15.4 (7051.0.79) from the fictional DOCX generated by `python3 scripts/generate-pages-source.py /tmp/pages-input.docx`. Open that DOCX in Pages and save it as a modern `.pages` file, then run `python3 scripts/prepare-pages-fixture.py saved.pages Tests/SwiftDocumentsTests/Fixtures/pages-15.4.pages`. The Pages UI was inspected for the Japanese/emoji paragraph, table/header cells, checkerboard image, alternative text and dimensions. Expectations are taken from the generated source and observed UI, not from this reader. The sanitizer removes root printer field 43, previews and unused template images, normalizes plist UUIDs and ZIP timestamps, and independently re-encodes IWA chunks; all other IWA message payload bytes are preserved. Only the generated 8×8 checkerboard PNG remains as media. A copy of the sanitized fixture was reopened in Pages and its text, table and image display were verified. Pages may assign different internal IDs on regeneration; inspect the graph and update the asset-path expectation after verifying unchanged content. This fixture verifies this import/save path only, not arbitrary native Pages features.
